# VDF Bracket — подключение к Supabase

Приложение теперь работает через облако: все видят одни и те же сетки в реальном времени, редактировать сетку может только её автор.

## Как это устроено

- **Вход:** при первом запуске просим никнейм и создаём анонимную сессию Supabase (`signInAnonymously`). Уникальный ID пользователя — `auth.uid()`, создаётся автоматически.
- **Никнейм** — только отображаемое имя (хранится в профиле сессии и в строке турнира), не подтверждение личности.
- **Владелец** определяется по `owner_id = auth.uid()`. Права проверяет база (RLS), а не только интерфейс: чужую сетку нельзя изменить даже прямым запросом.
- **Реалтайм:** подписка на `postgres_changes` таблицы `public.tournaments`. Чужие правки приходят сразу; при переподключении и возврате на вкладку список перезагружается.
- Анонимная сессия живёт в браузере. Если очистить данные сайта, доступ к своим сеткам потеряется (восстановления на другом устройстве нет).

## Настройка (один раз)

1. Authentication → Sign In / Providers → включить **Anonymous Sign-Ins**.
2. SQL Editor → выполнить весь `supabase-setup.sql` (создаёт таблицу, RLS-политики и включает Realtime).
3. Project Settings → API → скопировать **Project URL** и **anon / publishable key**.
4. В `index.html` в начале скрипта вставить их в `SUPABASE_URL` и `SUPABASE_KEY`.
5. Никогда не вставлять `service_role` key в приложение.
6. Залить файлы на хостинг по HTTPS (GitHub Pages, Netlify, Vercel и т.п.).

## Что проверить после запуска

- Открыть сайт в двух браузерах (или обычное окно + инкогнито): у каждого свой никнейм и ID.
- Создать сетку в первом браузере: она сразу появляется во втором, без перезагрузки.
- Нажать «Победа» в первом: во втором сетка обновляется, кнопки редактирования скрыты.
- Удалить сетку в первом: из второго она пропадает.

## Старые локальные турниры

При первом запуске приложение предложит загрузить турниры из `localStorage` в облако (один раз).
